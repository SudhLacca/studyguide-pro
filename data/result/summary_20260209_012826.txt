**Software Development Life Cycle (SDLC)** The SDLC is a structured process to build software in a systematic and efficient manner, consisting of the following phases: 1. **Planning** - Identify stakeholders, requirements, and feasibility. 2. **Designing** - Design system architecture, data models, user interface, and technology stack. 3. **Developing** - Break down modules, assign tasks, code as per design, and use version control. 4. **Testing** - Unit testing, integration testing, system testing, user acceptance testing, and bug fixing. 5. **Deployment** - Prepare production environment, deploy to server/cloud, monitor for runtime errors, and release to users. 6. **Maintenance** - Fix bugs, add new features, improve performance, and handle software upgrades. **Software Testing Life Cycle (STLC)** The STLC is a process to ensure that software meets requirements and is defect-free. It consists of the following phases: 1. **Requirement Analysis** - Understand what needs to be tested, identify testable requirements, and prepare requirement traceability matrix. 2. **Test Planning** - Define the overall testing strategy, decide scope, objectives, resources, and select tools and environments. **Principles of Software Testing** 1. **Testing shows the presence of defects, not their absence**. 2. **Exhaustive testing is impossible**. 3. **Early testing saves time and money**. 4. **Defect clustering (most bugs in few modules)**. 5. **Pesticide paradox (same tests find fewer new bugs)**. 6. **Testing is context-dependent**. 7. **Absence of errors ≠ Useful software**. **Integration Testing** Integration testing is a method to test how different units or components of a software application interact with each other. It is used to identify and resolve issues that may arise when different units of the software are combined. **Different Ways of Performing Integration Testing** 1. **Top-down integration testing** - Start with the highest-level modules and differentiate them from lower-level modules. 2. **Bottom-up integration testing** - Start with the lowest-level modules and integrate them with higher-level modules. 3. **Big-Bang integration testing** - Combine all modules and integrate them all at once. 4. **Critical Path First** - Test critical components first. **Big Bang Approach in Integration Testing** Big Bang Integration Testing is an approach where all modules of the system are integrated at once, rather than in phases. This method does not use incremental integration and is typically applied when all components are developed and available simultaneously. **Advantages and Disadvantages of Big Bang Integration Testing** Advantages: 1. **Simple and Time-Saving (Initially)** - Since everything is tested together, there is no need for test drivers or stubs. 2. **Suitable for Small Systems** - Works well for small applications with a limited number of modules. 3. **Less Planning Required** - Unlike phased integration, no complex test schedules are needed. Disadvantages: 1. **High Risk of Failure** - Since all modules are integrated at once, major system failures may be detected late. 2. **Difficult Debugging** - If the system fails, it is hard to pinpoint the root cause, as all modules are tested together. 3. **Delayed Testing & Feedback** - Testing occurs only after all modules are complete, leading to late defect detection.
